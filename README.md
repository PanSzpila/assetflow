# AssetFlow

AssetFlow is a portfolio project for tokenized assets and delivery-versus-payment (DvP) settlement on Canton.

The project is built in four stages. The goal is to demonstrate not only Daml contract development, but also a realistic application boundary between a Next.js UI, a Java backend, and a Canton ledger.

## Technology choices

- **Frontend:** Next.js App Router, React, TypeScript, Material UI.
- **Backend:** Java. Start with a small Spring Boot API when the first real backend use case is needed.
- **Smart contracts:** Daml SDK 3.5.2 as an initial pinned SDK version. Check the official release/install guidance before upgrading.
- **Ledger integration:** Canton Ledger API / JSON Ledger API v2, subject to the selected local Canton distribution.
- **Build tools:** npm workspaces for JavaScript packages; Maven for Java; DPM for Daml.
- **Database:** none initially. Add PostgreSQL only when the application has a clear need for durable off-ledger data or indexed history.

> `node_modules/` is generated by `npm install`; it is not a source file and should not be committed. This starter contains `package.json` files and `.gitignore` rules instead.

## Getting started (scaffold only)

Prerequisites:
- Node.js LTS compatible with the selected Next.js release
- npm
- JDK 17 or newer
- Maven
- DPM / Daml SDK
- A local Canton environment compatible with the selected Daml SDK

Commands after the initial application files are generated:

```bash
npm install
npm run dev
```

The web app is expected at `apps/web`. The first milestone is to make the UI shell run before connecting it to a ledger.

## Development principles

1. Keep Daml contracts authoritative for on-ledger business rules.
2. Keep frontend presentation separate from business rules and Canton API credentials.
3. Put ledger integration behind Java service interfaces so UI code never talks directly to Canton.
4. Do not treat a locally running Canton ledger as a public-network deployment.
5. Test privacy as an access-control property, not merely as a UI hiding/showing exercise.
6. Build the smallest working slice before adding infrastructure.
